## Plan: Multi-Tenant CRM with AI Chatbot and Mobile App

Build a comprehensive multi-tenant CRM system with user-centric organization management, Client Portal for external contacts, AI chatbot (web/mobile/Telegram via ngrok), native Android app, Deals Kanban, Contacts management, Issues tracking (Jira-ready structure), Activities logging, Agora voice calls, real-time WebSocket notifications, and file attachments. Fresh database schema with strict multi-tenant isolation.

### Steps

1. **Design fresh database schema and create comprehensive `.env` configuration** – Build schema.sql with tables: `users` (unified accounts with `user_type`: 'internal'/'client'), `organizations`, `user_organizations` (roles: owner/admin/manager/agent/viewer with membership validation), `contacts_people`, `contacts_organizations`, `deals`, `deal_stages`, `issues` (with `jira_project_key` placeholder), `activities` (call logs, deal changes, entity tracking), `files` (local storage at `Backend/uploads/`), `notifications`. Add to .env: Agora credentials (single shared account), Gemini API key, Telegram bot token, ngrok static domain, JWT secret, WebSocket port. Include Google OAuth placeholders (commented out for future).

2. **Rebuild authentication system with organization-aware JWT** – Update auth.js to extract `userId` + `currentOrganizationId` from JWT and validate user membership in organization before proceeding (strict multi-tenant isolation). Create `Backend/controllers/authController.js` for unified signup/signin (users must create account first). Add organization switcher endpoint that issues new JWT with different `currentOrganizationId`. Build `Backend/controllers/organizationController.js` for create org, add user by email lookup (existing users only), list user's orgs. Update `Frontend/src/components/OrganizationSwitcher.jsx` dropdown in dashboard header.

3. **Implement Client Portal and organization CRM modules** – Rebrand Customer Dashboard to Client Portal in `Frontend/src/pages/client/` where external contacts (`user_type='client'`) view their own deals/issues across all organizations. Build organization dashboard modules: Deals Kanban with `@dnd-kit/core` in `Frontend/src/pages/organization/Deals.jsx`, Contacts split into People and Organizations in `Frontend/src/pages/organization/Contacts.jsx`, Issues with basic CRUD and Jira-ready fields (`jira_ticket_id`, `jira_url`) in `Frontend/src/pages/organization/Issues.jsx`, Activities timeline with filtering in `Frontend/src/pages/organization/Activities.jsx`. All backend controllers validate `organizationId` from JWT.

4. **Integrate Agora voice calls, activity logging, and file uploads** – Implement Agora SDK in `Backend/services/agoraService.js` (single shared account for all orgs) and `Frontend/src/services/agoraService.js`. Build voice call UI in `Frontend/src/components/VoiceCall.jsx` for calling contacts. Auto-log all major actions to `activities` table: call start/end, deal stage changes, contact creation, file uploads. Create file upload endpoint in `Backend/routes/fileRoutes.js` storing to `Backend/uploads/` with `organization_id` isolation. Activity logging middleware in `Backend/middleware/activityLogger.js`.

5. **Build real-time WebSocket infrastructure and MCP chatbot server** – Add Socket.io to index.js for real-time notifications, create `Backend/services/socketService.js` with room-based isolation per `userId:organizationId`. Emit events on new activities, deal updates, incoming messages. Build separate MCP server in index.js (different port) with Gemini CLI integration, session keyed by `userId:organizationId`, explicit org validation on every action. Expose chatbot API in `Backend/routes/chatbotRoutes.js`. Create Telegram bot in index.js with one-time code linking (users generate 6-digit code in settings, enter in bot). Add chat UI in `Frontend/src/components/Chatbot.jsx` with WebSocket integration. Configure webhook to ngrok static domain.

6. **Develop native Android app with organization switching and FCM push notifications** – Create Android project in `AndroidApp/` using Kotlin, Retrofit for REST API, JWT authentication shared with web. Implement sliding drawer navigation with organization switcher at top (tapping switches `currentOrganizationId` in JWT, reloads entire app context). Build screens: Organizations list, Deals Kanban, Contacts, Issues, Activities, Settings. Integrate Agora Android SDK for voice calls, embed chatbot interface with WebSocket connection. Add Firebase Cloud Messaging (FCM) for push notifications when app is closed (notifications sent via `Backend/services/notificationService.js`). Implement offline-first with Room database for local caching, sync on reconnect.

### Further Considerations

1. **Organization ownership transfer** – If an organization owner leaves, should ownership transfer to another admin, or should organizations be deletable only when empty? Recommend: Owner can designate successor admin before leaving, system prevents orphaned organizations.

2. **Client Portal registration flow** – Should external clients self-register, or must they be invited by organization users? Recommend: Organization users add clients via email (creates `user_type='client'` account with temporary password sent via email), clients log in and change password.

3. **WebSocket reconnection strategy** – Mobile users may have unstable connections. Should missed real-time events be queued? Recommend: Store last 100 notifications per user in database, client fetches missed notifications on reconnect by timestamp.

4. **MCP server scaling** – Running separate MCP process requires process management. Use: (A) PM2 for process monitoring, (B) Docker Compose to run both services, or (C) single Node cluster with worker processes? Recommend: Docker Compose for clean separation and easy university deployment.

5. **File upload limits and security** – What file types/sizes allowed? Should virus scanning be implemented? Recommend: Limit to 10MB per file, whitelist extensions (.pdf, .docx, .jpg, .png), validate MIME types. Skip virus scanning for university project, add in production.

6. **Deal pipeline customization** – Should each organization define custom deal stages, or use global stages (Lead → Qualified → Proposal → Negotiation → Won/Lost)? Recommend: Start with global stages in `deal_stages` table, add per-org customization in phase 2 via `organization_deal_stages` table.
